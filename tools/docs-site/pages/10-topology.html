实例拓扑用于确认「当前连的到底是谁」：单机主从关系、哨兵与主节点、集群分片与槽位分布。 页面只做只读发现，不会触发主从切换、故障转移或槽位迁移。

自动发现

进入页面时会自动发现一次；也可以点「重新发现」刷新。发现方式随连接模式不同：

连接模式发现方式展示内容
单机（standalone） 读取 INFO 的 replication 段。 当前节点角色、已连接副本列表与状态。
哨兵（sentinel） 依次尝试哨兵地址，执行 SENTINEL get-master-addr-by-name 与副本查询。 主节点、副本、哨兵节点及副本链路状态。
集群（cluster） 通过种子节点执行 CLUSTER SLOTS。 分片数量、每个槽位区间的主 / 从节点、节点 ID。

单机主从视图

单机模式展示一张节点表：当前连接的主节点，以及 connected_slaves 中列出的副本。副本状态为 online 表示链路正常；其他状态会以红色提示。

  • 如果连接的是副本，表格中该节点角色会显示为 replica。
  • 主从关系来自 INFO replication，不是通过扫描网络发现。
  • 主从切换后，重新发现即可看到新的角色关系。

哨兵视图

哨兵模式会展示三类节点：当前主节点、副本、参与发现的哨兵节点。 主节点地址来自哨兵返回结果，而不是连接表单中填写的地址。

  • 至少需要一个可达的哨兵节点；全部不可达时页面提示「无法连接任何哨兵节点」。
  • 副本状态取自哨兵的 master-link-status。
  • 哨兵自身启用认证时，使用连接配置中的「哨兵用户名 / 密码」。

集群分片视图

集群模式按槽位区间聚合为分片卡片，每个分片显示：

  • 槽位范围（如 0-5460）；
  • 主节点地址与节点 ID 前 12 位；
  • 该分片下的副本节点。
分片视图是发现结果
分片与角色来自 CLUSTER SLOTS 的返回顺序。扩缩容或故障转移进行中， 拓扑可能短暂不一致；以 CLUSTER INFO / CLUSTER NODES 的完整输出为准。

注意事项

  • 拓扑发现不会修改任何节点状态，也不会执行 FAILOVER、SETSLOT 等操作。
  • 集群连接只从一个种子节点发现拓扑；如果种子节点不可用，连接本身也无法打开。
  • 网络 ACL、NAT 或端口映射可能导致返回的节点地址无法从本机直连；这种情况下连接可能需要 SSH 隧道或额外网络配置。
  • 页面展示的是发现瞬间的快照，不会自动轮询刷新。
