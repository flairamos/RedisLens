发布订阅

发布订阅页面用于观察频道消息与验证事件链路：可以同时订阅普通频道和模式频道， 查看实时消息流，也可以向指定频道发布消息。

订阅频道

  • 「频道」填写一个或多个频道名，用英文或中文逗号分隔，例如 news, chat:room:1。
  • 「模式订阅」填写 glob 模式，例如 news.*, chat:*；匹配到的消息会显示 pmessage 标记与原模式。
  • 至少填写一个频道或模式后，「订阅」按钮才可用。
  • 订阅中会显示「订阅中 · N 条」标记；点「退订」停止当前会话。
  • 离开页面或关闭连接会自动退订，避免后台悬挂订阅。
订阅使用 SUBSCRIBE / PSUBSCRIBE
页面只使用普通订阅与模式订阅。集群的 sharded pubsub（SSUBSCRIBE 等） 需要在命令行控制台手动执行。

实时消息流

列说明
时间消息到达客户端的时间（毫秒级）。
类型message、pmessage、subscribe 等。
频道消息所属频道；模式订阅时还会显示匹配的模式。
负载消息内容；非 UTF-8 或含 NUL 的负载以 Base64 斜体显示。
  • 消息每 300 ms 批量刷新一次，避免高频消息导致界面卡顿。
  • 界面最多保留最近 1000 条，超出后丢弃最旧的。
  • 「暂停接收」只暂停界面追加，恢复后继续显示缓冲消息。
  • 垃圾桶按钮清空当前消息列表，不影响订阅本身。
  • 切换实例会清空消息列表，需要重新订阅。

发布消息

  • 填写频道与负载，点「发布」；返回成功送达的订阅者数量（PUBLISH 的返回值）。
  • 只读模式下「发布」按钮禁用，后端也会拒绝 PUBLISH。
  • 发布不会持久化消息：没有在线订阅者时，消息直接丢弃。

监听键空间事件

Redis 的键空间通知（keyspace notifications）以 Pub/Sub 形式发出。启用后， 可以在本页订阅例如 __keyevent@0__:expired 来观察过期事件： 

# 在控制台（危险命令，需要二次确认）
CONFIG SET notify-keyspace-events KEA

然后在「频道」中订阅：

__keyspace@0__:user:*
__keyevent@0__:expired
__keyevent@0__:del
键空间通知会增加额外开销
notify-keyspace-events 打开后，Redis 会为每个事件发送消息。 生产环境建议只开启需要的类别（如仅 Ex），并在使用完毕后关闭。

边界与注意事项

  • 无历史：Pub/Sub 是即发即忘的，订阅之前的消息不可回放；需要持久化请使用 Stream。
  • 无确认：没有 ACK、重试或消费组语义，网络中断期间的消息会丢失。
  • 单会话：每页同时只有一个订阅会话；重新订阅会替换旧会话。
  • 不替代监控：消息数量只代表当前页面接收到的数量，不是实例的发布总量。
  • 高频频道可能造成界面刷新压力；必要时用模式订阅收窄范围，或改用控制台导出到文件。
