开发者指南

本页面向希望从源码构建、二次开发或维护文档站的开发者。应用使用 Go + Wails v2， 前端为 Vue 3 + TypeScript + Vite；文档站是零依赖的静态 HTML，由 tools/docs-site 生成到 docs/。

技术栈与目录

层技术位置
桌面外壳 / 绑定层Wails v2、Go 1.26main.go、app.go
Redis 服务层go-redis v9、SSH 隧道、TLSinternal/rds
配置与凭据JSON + AES-256-GCM + HKDFinternal/config
审计JSONL 月度轮转internal/audit
命令分类读 / 写 / 危险 / 阻塞internal/security
前端Vue 3、TypeScript、Vite、ECharts 5frontend/src
文档站静态 HTML/CSS/JS + Node 构建脚本tools/docs-site → docs/
 
RedisLens/
├── main.go / app.go        # Wails 入口与绑定层
├── internal/
│   ├── config/             # 配置存储 + 凭据加密
│   ├── rds/                # 连接、键、监控、控制台、分析、导入导出、PubSub、拓扑
│   ├── audit/              # 审计日志（JSONL 月度轮转）
│   └── security/           # 命令分类与危险命令拦截
├── frontend/               # Vue 3 前端
├── build/                  # 构建产物（exe / NSIS 安装包）
├── docs/                   # GitHub Pages 站点（构建输出）
└── tools/
    ├── docs-site/          # 文档源片段与生成脚本
    └── genlogo/            # 品牌图标生成器

环境要求

  • Go 1.26+
  • Node.js 22+ 与 npm
  • Wails CLI v2.10.1
  • Windows 10 / 11 x64 与 WebView2
  • 构建 NSIS 安装包时，额外需要 makensis 在 PATH 中
go install github.com/wailsapp/wails/v2/cmd/wails@v2.10.1
wails doctor

本地开发

# 安装前端依赖
cd frontend
npm ci
cd ..

# 开发模式：前端热更新 + Go 后端
wails dev

wails dev 会启动 Vite 开发服务器并把资源注入桌面窗口。 修改 Go 绑定方法后需要重新编译；前端页面通常热更新。

生产构建

# 仅可执行文件，产物在 build/bin/
wails build -platform windows/amd64

# 同时生成 NSIS 安装包（需 makensis）
wails build -platform windows/amd64 -nsis

构建会先执行前端生产构建，再由 Wails 把 frontend/dist 嵌入二进制。 产物为 build/bin/RedisLens.exe 与 build/bin/RedisLens-amd64-installer.exe。

测试

# 单元测试 + 集成测试（自动探测本机 redis-server，无则回退 miniredis）
go test ./internal/...

# 指定真实 Redis 实例
REDISLENS_TEST_ADDR=127.0.0.1:6379 go test ./internal/rds

PowerShell 中设置环境变量：

$env:REDISLENS_TEST_ADDR = "127.0.0.1:6379"
go test ./internal/rds

仓库还使用 gosec、staticcheck、govulncheck 做安全与静态检查；发布前建议全部清零。

发布流程

.github/workflows/release.yml 在推送 v* 标签时触发， 在 windows-latest 上安装 Go / Node / Wails / NSIS，执行 wails build -platform windows/amd64 -nsis，并创建 GitHub Release。 

git tag v1.0.0
git push origin v1.0.0
  • 工作流会把标签版本写入 wails.json 的 info.productVersion。
  • 发布产物：便携版 RedisLens.exe 与安装包 RedisLens-amd64-installer.exe。
  • 手动触发 workflow_dispatch 只做构建验证，不创建 Release。

文档站如何生成

docs/ 是 构建输出目录，不要直接改其中的 HTML。 内容源在 tools/docs-site/pages/，统一布局、导航与搜索索引由 tools/docs-site/build.mjs 生成。 

# 修改 tools/docs-site/pages/*.html 或 site.mjs 后执行
node tools/docs-site/build.mjs
路径作用
tools/docs-site/site.mjs站点元信息、导航分组、页面标题与描述。
tools/docs-site/pages/*.html每页正文片段，不含页头、侧栏与页脚。
tools/docs-site/build.mjs套用布局、补标题锚点、生成搜索索引 / sitemap / robots。
docs/assets/docs.css站点样式（浅色 / 深色、响应式、打印）。
docs/assets/docs.js主题、移动端导航、目录、代码复制与搜索交互。
docs/assets/search-index.js构建生成的全文搜索索引。
docs/.nojekyll关闭 GitHub Pages 的 Jekyll 处理。

新增一页文档

  1. 在 tools/docs-site/pages/ 新建 HTML 片段，只写正文（从 <p class="lead"> 开始）。
  2. 在 site.mjs 的对应分组中登记 file / src / label / title / description。
  3. 运行 node tools/docs-site/build.mjs，确认输出无报错。
  4. 本地预览并检查导航、目录与搜索，然后一并提交 tools/ 与 docs/。

部署到 GitHub Pages（Deploy from a branch）

本站使用「从分支部署」而不是 GitHub Actions 构建。仓库 Settings 中的配置只需做一次：

  1. 推送到默认分支 确保 docs/index.html、docs/assets/ 与 docs/.nojekyll 已经提交并推送到 main。
  2. 打开 Pages 设置 进入 GitHub 仓库 → Settings → Pages。
  3. 选择来源 Build and deployment → Source 选择 Deploy from a branch。
  4. 选择分支与目录 Branch 选择 main，Folder 选择 /docs，点击 Save。
  5. 等待首次发布 仓库的 Actions 页会出现 pages build and deployment 运行记录； 完成后访问 https://<用户名>.github.io/<仓库名>/。
本站地址
按当前仓库配置，地址为 https://flairamos.github.io/RedisLens/。 如果仓库改名或使用自定义域名，请在 site.mjs 中同步 baseUrl 并重新构建。

为什么需要 .nojekyll

「Deploy from a branch」默认会让 Jekyll 处理站点。本站是纯静态 HTML， 不需要 Jekyll；在 docs/ 根目录放置空的 .nojekyll 可以跳过 Jekyll，避免以下划线开头的文件被忽略，并减少构建失败点。

部署后检查

  • 访问首页，确认样式、Logo 与截图加载正常（资源使用相对路径）。
  • 打开任意内页，确认左侧导航、右侧目录与「上一篇 / 下一篇」正常。
  • 按 Ctrl + K 搜索，确认搜索结果能跳转到对应锚点。
  • 访问一个不存在的路径，确认 404.html 生效。
  • 如果页面仍是旧版本，等待 Pages 构建完成并强制刷新缓存。
不要同时启用 Actions 部署
如果仓库同时存在自定义 Pages Actions 工作流，可能与分支部署互相覆盖。 本项目刻意只使用「Deploy from a branch → /docs」这一种方式。
